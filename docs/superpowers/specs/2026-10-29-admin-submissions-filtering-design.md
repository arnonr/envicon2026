# Admin Submissions Search & Filtering — Design Spec

Date: 2026-10-29

## Intent & Why

เพิ่มความสามารถในการค้นหาและกรองรายการผลงานในหน้าจัดการผลงานของผู้ดูแลระบบ (`/admin` — `frontend/pages/admin/index.vue`) เพื่อให้ Admin ค้นหาผลงานจากชื่อเรื่องหรือชื่อผู้ส่ง กรองตามรูปแบบการนำเสนอ ผู้รีวิว และคุณลักษณะอื่นๆ ของผลงานได้อย่างรวดเร็ว รองรับการทำงานร่วมกับการแบ่งหน้า (Pagination) และการส่งออกไฟล์ Excel (`Export Excel`) ให้ตรงกับเงื่อนไขที่กรองอยู่

## Size

**A small change** — แก้ไขเฉพาะ 2 ไฟล์ที่มีอยู่แล้ว (`backend/src/routes/admin.ts` และ `frontend/pages/admin/index.vue`) โดยไม่ต้องเพิ่มตารางหรือแก้ไขโครงสร้างฐานข้อมูล

## Goals, Non-Goals, Anti-Goals

- **Goals:**
  - ค้นหาข้อความแบบรวมในช่องเดียว (ชื่อเรื่องไทย/อังกฤษ, ชื่อ-อีเมล-สังกัดผู้ส่ง, ชื่อผู้แต่งร่วม)
  - กรองตามรูปแบบการนำเสนอ (`บรรยาย`/`โปสเตอร์`) และผู้รีวิว (เลือกชื่อผู้รีวิว หรือเลือกผลงานที่ยังไม่ได้กำหนดผู้รีวิว)
  - กรองเพิ่มเติมตามประเภทผู้ส่ง, ระดับการศึกษา, ความประสงค์ส่ง Full Paper และสถานะไฟล์แนบ
  - แสดงรายชื่อผู้รีวิวของรอบล่าสุดในตารางหน้า `/admin` เพื่อตรวจสอบผลการกรองได้ทันที
  - ใช้เงื่อนไขตัวกรองชุดเดียวกันทั้งในตาราง `GET /admin/submissions` และปุ่ม `GET /admin/submissions/export`
- **Non-Goals:**
  - ไม่เปลี่ยนโครงสร้างฐานข้อมูลหรือขั้นตอนการมอบหมายผู้รีวิวใน `AdminSubmissionDetailModal.vue`
- **Anti-Goals:**
  - ห้ามทำให้ส่วนหัวของตารางรกจนดันตารางลงไปลึกเมื่อไม่ได้เปิดใช้ตัวกรองรอง
  - ห้ามทำให้จำนวนรายการรวม (`total`) เพี้ยนซ้ำซ้อนเมื่อผลงาน 1 ชิ้นมีผู้รีวิวหลายคนหรือหลายรอบรีวิว

## Constraints

- ตารางใช้ Server-side Pagination (`50` รายการต่อหน้า) การค้นหาและกรองทั้งหมดจึงต้องประมวลผลใน SQL ฝั่ง Backend (`backend/src/routes/admin.ts`)
- การกรองตามผู้รีวิวต้องใช้ `EXISTS` / `NOT EXISTS` subquery แทนการ `JOIN` ตรงกับตารางหลัก เพื่อไม่ให้แถวผลงานซ้ำซ้อนในการนับจำนวน (`count(*)`) และการแบ่งหน้า

## Approaches Considered

1. **Approach 1 (Chosen): กรองฝั่ง Backend + แถบค้นหาหลักคู่กับปุ่ม "ตัวกรองเพิ่มเติม" แบบพับ/กางได้**
   - วางช่องค้นหาและตัวกรองหลักที่ใช้บ่อยไว้แถวแรก ส่วนตัวกรองรองพับเก็บไว้ใต้ปุ่ม *"ตัวกรองเพิ่มเติม"* พร้อมตัวนับจำนวนตัวกรองที่เปิดใช้งาน ปุ่มล้างตัวกรอง และเชื่อมเงื่อนไขทั้งหมดกับ Export Excel
   - *Trade-off:* หน้าจอสะอาดไม่รก แต่ตัวกรองรองต้องคลิกกาง 1 ครั้งก่อนเลือก
2. **Approach 2: กรองฝั่ง Backend + แสดงตัวกรองทุกตัวเรียงเปิดไว้ตลอดเวลา (2–3 แถว)**
   - *Trade-off:* คลิกเลือกได้ทันทีทุกตัวกรอง แต่กินพื้นที่แนวตั้งเหนือตารางตลอดเวลา

ผู้ใช้งานเลือก **Approach 1** เพื่อรักษาความคล่องตัวของหน้าจอจัดการผลงาน

## Decisions (What Gets Built)

### 1. แถบค้นหาและตัวกรองหลัก (แสดงตลอดเวลาใน `frontend/pages/admin/index.vue`)
- **ช่องค้นหาข้อความ (`search`):** ค้นหาแบบไม่สนตัวพิมพ์เล็ก-ใหญ่ (Debounce ~300ms) ครอบคลุม `submissions.title`, `submissions.titleEn`, `submissions.creators`, `users.name`, `users.email`, `users.affiliation`
- **สถานะผลงาน (`status`):** ตัวเลือกเดิมทั้งหมด
- **การชำระเงิน (`paymentStatus`):** ตัวเลือกเดิมทั้งหมด
- **หัวข้อ (`track`):** ตัวเลือกเดิมทั้งหมด (Track 1–7)
- **รูปแบบการนำเสนอ (`presentationFormat`):** ทั้งหมด / แบบบรรยาย (`oral`) / โปสเตอร์ (`poster`)
- **ผู้รีวิว (`reviewerId`):** ดึงรายชื่อจาก `GET /admin/reviewers` (searchable `USelectMenu`) พร้อมตัวเลือกพิเศษ `"unassigned"` (*ยังไม่ได้กำหนดผู้รีวิวในรอบล่าสุด*)
- **ปุ่มควบคุม:** ปุ่ม *"ตัวกรองเพิ่มเติม"* (แสดง Badge จำนวนตัวกรองรองที่ถูกเลือก) และปุ่ม *"ล้างตัวกรอง"* (แสดงเมื่อมีการกรองอย่างน้อย 1 เงื่อนไข)

### 2. ตัวกรองเพิ่มเติมแบบพับ/กางได้ (Default Calls)
- **ประเภทผู้ส่ง (`submitterType`):** ทั้งหมด / นิสิต-นักศึกษา (`student`) / อาจารย์-นักวิจัย-บุคคลทั่วไป (`general`)
- **ระดับการศึกษา (`educationLevel`):** ทั้งหมด / ปริญญาตรี (`bachelor`) / ปริญญาโท (`master`) / ปริญญาเอก (`doctorate`)
- **ความประสงค์ส่ง Full Paper (`wantsFullPaper`):** ทั้งหมด / ต้องการส่ง Full Paper (`1`) / เฉพาะบทคัดย่อ (`0`)
- **สถานะไฟล์แนบ (`fileStatus`):** ทั้งหมด / มีไฟล์บทคัดย่อ (`has_abstract`) / มีไฟล์ฉบับสมบูรณ์ (`has_full_paper`) / ประสงค์ส่ง Full Paper แต่ยังไม่มีไฟล์ฉบับสมบูรณ์ (`missing_full_paper`) / ยังไม่มีไฟล์แนบ (`no_files`) — คำนวณรวม fallback ของ `round1_file_url` / `round1_file_type`

### 3. Backend Query & Export (`backend/src/routes/admin.ts`)
- แยกฟังก์ชันกลาง `buildAdminSubmissionWhere(query)` ให้ทั้ง `GET /admin/submissions` และ `GET /admin/submissions/export` ใช้ร่วมกัน (รวมการ `leftJoin(users, ...)` ใน query นับจำนวน `count(*)` ด้วย)
- ใน `GET /admin/submissions` ส่ง `reviewerNames: string[]` ของรอบรีวิวล่าสุดกลับไปพร้อมแต่ละแถว เพื่อแสดงรายชื่อผู้รีวิวใต้ตัวเลขความคืบหน้า (`completed/assigned`) ในตาราง และเพิ่มคอลัมน์รายชื่อผู้รีวิวในไฟล์ Excel ที่ Export

## Left to the Builder (Default Calls)

- ใช้ Debounce `300ms` สำหรับช่องพิมพ์ค้นหาเพื่อไม่ให้ยิง API ถี่เกินไปขณะพิมพ์ภาษาไทย/อังกฤษ
- เมื่อเลือกผู้รีวิวรายบุคคล (`reviewerId = <uuid>`) ให้ค้นหาจาก `EXISTS` ในตาราง `reviews` ของผลงานนั้น (ครอบคลุมทุกรอบที่ผู้รีวิวคนนั้นได้รับมอบหมาย) ส่วน `"unassigned"` ให้เช็กว่าในรอบล่าสุดยังไม่มีผู้รีวิวถูกมอบหมาย (สอดคล้องกับตัวเลข `0` ในคอลัมน์การรีวิวของกรรมการ)
- เพิ่มคอลัมน์ *"ผู้รีวิว (รอบล่าสุด)"* ในไฟล์ Export Excel เพื่อให้ข้อมูลที่ดาวน์โหลดสอดคล้องกับตัวกรองผู้รีวิว
